Synopsis

A beginner's guide to Windows kernel driver development covering environment setup, driver architecture, IRP handling, kernel debugging with WinDbg via VirtualKD Redux, and a CTF-style challenge driver built around XOR-encoded flag validation.

Tools: VMware Workstation 17 · Win10 ISO · VirtualKD Redux · WinDbg · Visual Studio 2022 · WDK

1. What is a Kernel Driver?

Think of Windows as a building with two floors. Normal applications — Chrome, Notepad, games — run on the ground floor in user mode. The basement is restricted: this is kernel mode, where the Windows core, hardware drivers, and low-level subsystems live. A kernel driver is a program that runs in the basement. One crash equals a Blue Screen of Death.

For Developers

FloorNameWho lives here
Ground floorUser modeYour apps — Chrome, Notepad, games
Basement (restricted)Kernel modeWindows core, hardware, drivers
  • Kernel drivers run at Ring 0 — highest CPU privilege level
  • Loaded as .sys files, not .exe
  • Communicate with userland via IRP (I/O Request Packets)
  • Interact with the Windows I/O Manager, not Win32 API
  • Bugs cause system crashes, not just process crashes

5. Code Walkthrough

DriverEntry — The Main Function

extern "C" NTSTATUS DriverEntry(PDRIVER_OBJECT DriverObject,
                                 PUNICODE_STRING RegistryPath)
{
    // 1. Create kernel device object
    IoCreateDevice(...);

    // 2. Create Win32-accessible symbolic link
    IoCreateSymbolicLink(...);

    // 3. Register IRP handlers
    DriverObject->MajorFunction[IRP_MJ_CREATE]         = drv_create;
    DriverObject->MajorFunction[IRP_MJ_CLOSE]          = drv_close;
    DriverObject->MajorFunction[IRP_MJ_DEVICE_CONTROL] = drv_ioctl;

    // 4. Register unload function
    DriverObject->DriverUnload = drv_unload;

    return STATUS_SUCCESS;
}

IRP Handler Pattern

Every IRP handler follows the same four-step pattern:

NTSTATUS drv_ioctl(PDEVICE_OBJECT device_object, PIRP irp) {

    // 1. Get the current stack location
    PIO_STACK_LOCATION stack = IoGetCurrentIrpStackLocation(irp);

    // 2. Get the user's data buffer (METHOD_BUFFERED)
    auto req = (MyRequest*)irp->AssociatedIrp.SystemBuffer;

    // 3. Do the work
    // ...

    // 4. ALWAYS complete the IRP — or the thread hangs forever
    irp->IoStatus.Status      = STATUS_SUCCESS;
    irp->IoStatus.Information = sizeof(MyRequest);
    IoCompleteRequest(irp, IO_NO_INCREMENT);
    return STATUS_SUCCESS;
}

7. Deploying to the VM

One-Time VM Setup (run as Admin on VM)

bcdedit /set testsigning on
bcdedit /debug on
bcdedit /dbgsettings net hostip:<HOST_IP> port:50000 key:1.2.3.4

Then reboot the VM.

Copy Driver to VM

Use VMware shared folder or drag-and-drop:

Host:  F:\Projects\KmdfHelloWorld\x64\Debug\KmdfHelloWorld.sys
VM:    C:\Drivers\KmdfHelloWorld.sys

Load / Unload Driver (VM, run as Admin)

rem ── Load ─────────────────────────────────────────────
sc create KmdfHelloWorld type= kernel binPath= C:\Drivers\KmdfHelloWorld.sys
sc start KmdfHelloWorld

rem ── Unload ───────────────────────────────────────────
sc stop KmdfHelloWorld
sc delete KmdfHelloWorld

VirtualKD Redux Flow

VMware Workstation 17
└── Win10 VM
    └── VirtualKD Redux VM Monitor installed
        └── On boot → auto-connects to WinDbg on host
            └── No F8 needed, no COM port needed

ed nt!Kd_IHVDRIVER_Mask 0xf
.sympath+ F:\Projects\KmdfHelloWorld\x64\Debug\
.reload /f KmdfHelloWorld.sys

Verify Driver Loaded

lm m KmdfHelloWorld*
!drvobj \Driver\KmdfHelloWorld 2

Setting Breakpoints

bp KmdfHelloWorld!DriverEntry
bp KmdfHelloWorld!drv_ioctl
bp KmdfHelloWorld!CheckFlag

Inspecting Memory at Breakpoint

da rcx          ← print ASCII string at address in RCX
db rbx          ← dump raw bytes at RBX
db rcx L40      ← dump 64 bytes from RCX
dq rsp          ← dump stack
r               ← show all registers

Stepping

p   ← step over
t   ← step into
pt  ← step to return
g   ← continue / go

9. CTF Challenge Driver

What It Does

A kernel driver that stores a secret flag encoded with XOR. Userland sends a guess; the kernel checks it and returns correct or wrong.

The XOR Encoding

Plain flag:    KCTF{1n7r0_70_K3rN3l_D3bUgg1nG}
XOR key:       0x5A
Stored as:     encoded bytes in .data section
               (not readable as plaintext in the .sys binary)

Decode at runtime:
    for each byte: decoded[i] = encoded[i] ^ 0x5A
    compare with user input using RtlCompareMemory
    immediately zero the decoded buffer (RtlSecureZeroMemory)

Security Design

FeatureWhy
XOR encodingFlag not visible as plaintext in binary
RtlSecureZeroMemoryDecoded flag wiped from kernel memory immediately after check
Buffer null terminationPrevents userland from causing overflow
Buffer size validationRejects malformed IOCTL requests
METHOD_BUFFEREDWindows safely copies data between kernel and userland

Solve It in WinDbg

bp CTFDriver!CheckFlag
g
da rcx              ← see the decoded flag before it gets wiped!
